Design patterns

Patterns used to keep the student management code organized and maintainable.

Learning note: This is a front-end demonstration. The patterns are implemented in JavaScript; a production system should add authentication, server-side validation, a database, and access control.

01 · Singleton

StudentStore has one shared instance for the app. It owns the current records and persistence layer, avoiding multiple competing copies of student data.

02 · Factory

StudentFactory.create() builds student objects in a consistent shape, normalizing IDs, names, course, year, status, and attendance.

03 · Observer

EventBus broadcasts a “students:changed” event after data changes. Dashboard cards, tables, and attendance summaries re-render in response.

04 · Strategy

Filter strategies provide interchangeable ways to filter records by name, status, or course. This keeps filtering logic separate from rendering.

05 · Module pattern

The StudentStore, StudentFactory, EventBus, and UI controller are separate modules with clear responsibilities.

06 · MVC-inspired UI

The data store acts as the model, UI controller handles user actions, and render functions update the views. This separation makes future changes easier.
